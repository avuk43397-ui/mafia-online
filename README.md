# DUB STUDIO

Браузерная мини-студия озвучки: ZIP/папка → импорт сцен → просмотр → оригинальный звук вкл/выкл → запись дублей → выбор основного дубля → сборка итогового MP4.

## Что поддерживается

- ZIP или папка с видео и текстами.
- MP4, WEBM, MOV, M4V, AVI.
- TXT, SRT, VTT, JSON.
- Автосопоставление видео и текста по имени файла и порядку.
- Два диктора: A и B.
- Несколько дублей каждой сцены.
- Прослушивание дубля, выбор основного и удаление.
- Кнопка «Слышать оригинал / Не слышать оригинал».
- Микрофон через MediaRecorder.
- Переключение реплик внутри сцены.
- Автоматический переход к следующей сцене после остановки записи.
- Экспорт итогового MP4 в браузере через FFmpeg.wasm.

## Формат dub-пака

Например:

```text
pack/
  01_intro.mp4
  01_intro.txt
  02_scene.mp4
  02_scene.srt
  03_scene.mp4
  03_scene.json
```

JSON может быть массивом:

```json
[
  {"start": 0, "end": 2.2, "text": "Первая реплика"},
  {"start": 2.2, "end": 5.7, "text": "Вторая реплика"}
]
```

## Локальный запуск

Нужен локальный HTTP-сервер, потому что микрофон работает только в защищённом контексте или на localhost.

```bash
python -m http.server 8080
```

Откройте `http://localhost:8080`.

## GitHub + Render

Этот проект уже подготовлен под Render через `render.yaml`.

1. Создайте новый репозиторий на GitHub.
2. Загрузите **все файлы из этой папки в корень репозитория**.
3. В Render выберите **New → Static Site** и подключите GitHub-репозиторий.
4. Можно оставить настройки из `render.yaml`. Если Render предлагает заполнить поля вручную:
   - Build Command: пусто
   - Publish Directory: `.`
   - Branch: `main`
5. После деплоя сайт будет доступен по HTTPS.

`render.yaml` также задаёт заголовки COOP/COEP, которые нужны для браузерных сценариев с изолированным исполнением WASM. Render позволяет задавать такие заголовки у Static Site. 

## Важное ограничение

Это **frontend-only** версия. Загруженный ZIP, видео и записи находятся в браузере пользователя и не сохраняются на сервере. Поэтому два компьютера не будут автоматически видеть одну и ту же комнату.

Для настоящей совместной работы с другом в реальном времени нужен отдельный backend: комнаты, аккаунты, WebSocket/WebRTC и хранилище файлов. Такой backend можно добавить на Render отдельным Web Service.

## Большие видео

FFmpeg.wasm собирает MP4 прямо на компьютере пользователя. Чем больше исходники, тем больше RAM/CPU требуется браузеру, поэтому длинные фильмы и очень большие 4K-файлы могут быть тяжёлыми.
